# Storybook architecture

How the Storybook setup of the kit is built. How to write stories: [CONTRIBUTING.md](../CONTRIBUTING.md#storybook).

## File tree

```text
.storybook/
├── main.ts                           Storybook config: story globs, addons, framework, static assets
├── manager.ts                        Storybook UI branding: logo, title, brand colour
├── preview.ts                        Wires everything for every story: providers, decorators, toolbar globals, parameters
├── providers.ts                      Root providers of every story (icons, HttpClient)
├── styles.scss                       Global styles: kit theme and fonts, Storybook fixes, layout classes for stories
├── tsconfig.json                     TS project of .storybook/ and all stories; entry-point aliases and @sb/*
├── typings.d.ts                      Type of the generated documentation.json
├── documentation.json                Generated by Compodoc on every start/build, git-ignored
├── decorators/
│   ├── with-theme.decorator.ts       Theme toolbar: puts ndwu-theme-light / ndwu-theme-dark on body
│   ├── with-size.decorator.ts        Size toolbar: its items and the wrapper around the story
│   └── size-provider.component.ts    Wrapper component that provides NDWU_SIZE_TOKEN from the toolbar
└── helpers/
    ├── story-args.ts                 SizeArg (host-directive size), AdaptiveSizeArg and AriaArgs (alias-keyed ARIA args)
    ├── arg-types.ts                  Shared argTypes: size, adaptive size, icon, text, boolean, outputs, native events
    ├── args-to-source.ts             "Show code" transform: argsToTemplate bindings -> literal attributes
    ├── story-layout.ts               Row, stack and box layout decorators, left out of "Show code"
    ├── story-viewport.ts             Size flags for adaptiveSize stories from the Breakpoints.Handset media query
    ├── story-controlled.ts           withControlledArgs: syncs a controlled value back into args
    ├── story-form.ts                 Native form stories: submit handler, its argType, form template and decorators
    ├── story-template.ts             Joins fixed story templates, one element per line, and groups them in rows
    ├── router-url.component.ts       Wrapper that shows the current Router URL below a story
    └── story-router.ts               Story-level Router providers, RouterLink import and URL wrapper
```

Stories live next to their components: `src/lib/**/<component-file-name>.stories.ts`. The first model is
`src/lib/core/components/button/button/ndwu-button.stories.ts`. Pages that don't belong to one component, such as the
home page, live in `src/storybook/` (see [Home page](#home-page)).

## Files

### Config

| File | What it does | Why it is built this way |
|---|---|---|
| `main.ts` | Story globs `src/storybook/**/*.mdx`, `src/storybook/**/*.stories.ts`, `src/lib/**/*.stories.ts`; addons docs, a11y, themes (a11y runs [axe](https://github.com/dequelabs/axe-core), an automated accessibility checker, on every story and lists the violations, such as low text contrast, in the Accessibility panel); serves `src/lib/assets` at `/assets` and `src/storybook/assets` at `/sb-assets`; telemetry off; `angularFilterNonInputControls` | Icons, pictograms and fonts use `assets/...` URLs, so the assets folder must be served at `/assets`. The filter keeps Compodoc's public non-input members out of the controls |
| `preview.ts` | Registers the Compodoc JSON, `applicationConfig` with `STORYBOOK_PROVIDERS`, the decorators, the Size global, the `surface` background, `controls.expanded`, `docs.source.excludeDecorators`, a11y defaults, `storySort` with `Introduction` first | The only file Storybook loads for every story. It imports and registers; logic lives in `decorators/` and `helpers/` |
| `manager.ts` | `addons.setConfig` with a light theme: `brandTitle`, `brandImage: 'sb-assets/logo.svg'`, `colorSecondary` `#007bbe` (`--ndwu-color-brand-50`) | The manager UI is outside the preview iframe and doesn't load kit styles, so the brand colour is a literal. A relative image path keeps a sub-path deploy working |
| `providers.ts` | `provideHttpClient()`, `provideNdwuAllIcons()` | Separate, so later providers (e.g. localization) are added here without touching `preview.ts`. Zoneless is not here: the builder flag `experimentalZoneless` adds the provider |
| `styles.scss` | `@use 'styles/themes'` with font faces; `transition: none` on the canvas; `.sb-row`, `.sb-stack` (also stacks a direct `<form>` child), `.sb-box` (160 px host for `stretched` components), `.sb-note`; `.sbdocs-wrapper` / `.sbdocs-content` `:has(sb-introduction)` rule | The theme as the playground uses it. The backgrounds addon animates the canvas colour change over 0.3s. In the dark theme, [axe](https://github.com/dequelabs/axe-core) (the accessibility checker of the a11y addon, see `main.ts`) could run during that animation, compare the text with the still-light background and report contrast errors that don't exist; `transition: none` removes the animation. The layout classes keep inline styles out of "Show code". The home page's docs frame is React DOM outside the component; the rule paints it with the kit surface and drops its padding and max-width so Dark covers the whole page |
| `tsconfig.json` | Own TS project for `.storybook/**`, `src/lib/**/*.stories.ts`, `src/storybook/**`; kit entry-point aliases; `@sb/*` → `.storybook/*` | `tsconfig.lib.json` excludes stories, so they don't reach the package; this project lets ESLint (`projectService`) and the Storybook builder still type-check them |
| `typings.d.ts` | Declares `*/documentation.json` | The file exists only after Compodoc ran; the declaration keeps `yarn lint:ts` green on a fresh clone |

### Decorators

The order in `preview.ts` is `applicationConfig`, `withSizeProviderImport`, `withSize`, `withTheme`.

| File | What it does | Why it is built this way |
|---|---|---|
| `with-theme.decorator.ts` | Reads the `theme` global (addon-themes toolbar) and sets the `ndwu-theme-*` class on `body` before the story renders; unknown values fall back to light | Popovers look up the theme on ancestors of the trigger, modals read `body`. The addon's own `withThemeByClassName` sets the class after render, so a dialog opened on story load had no theme |
| `with-size.decorator.ts` | Size toolbar (`component default`, S, L, XL, XXL); for a size from the story's `parameters.sizes` wraps the story in `sb-size-provider`, for any other size shows a "not supported" note instead | Components read size through `NDWU_SIZE_TOKEN` (as inside `ndwu-form-container`), not through a class. `component default` adds no wrapper, so the component falls back to its own default (XL). Toolbar items are global and can't be hidden per story, so an unsupported size falls back to the default with a note |
| `size-provider.component.ts` | `display: contents` component that provides `NDWU_SIZE_TOKEN` as `() => sbToolbarSize()` | The token is a signal getter, so S → L → XXL updates the running story without re-render. Dialogs from `NdwuModalService` use the root injector and get the size only with `{injector}` (CONTRIBUTING) |

### Helpers

Imported by stories as `@sb/helpers/<file>`.

| File | What it does | Why it is built this way |
|---|---|---|
| `story-args.ts` | `SizeArg` for the `NdwuSizeDirective` host directive; `AdaptiveSizeArg` (`unbound` / `viewport`) for the `NdwuAdaptiveSizeDirective` host directive; `AriaArgs` for aliased ARIA inputs | `size` comes from a host directive, not from the component class, so Storybook's `Meta<Component>` doesn't see it. The other args are typed by `Meta<Component & Extra>`, which maps signal inputs, outputs and `model()` itself. Compodoc names aliased inputs by alias, so their args are keyed the same way and the ArgTypes table has one row per input |
| `arg-types.ts` | `sizeArgType(sizes)` (`inherit` = `undefined`, then the sizes the component supports), `iconArgType` (`none` = `null`), `adaptiveSizeArgType(description)` (`unbound` / `viewport`, typed as `NdwuSizeFlags` in the table), `textArgType`, `booleanArgType`, `outputArgType`, `eventArgType` | One definition for every component with a size, an icon or outputs. Not every component supports every size, so each story passes its own list. Compodoc's output docs are filtered out, so outputs and events are declared here |
| `args-to-source.ts` | `argsSourceTransform`: `[variant]="variant"` and `[aria-label]="this['aria-label']"` → literal attributes, drops event bindings, fills `{{ content }}` | "Show code" is what app developers copy, so it must be plain markup with the current values |
| `story-layout.ts` | `withRowLayout`, `withStackLayout`, `withBoxLayout` (160 px `.sb-box` the `stretched` component fills) | Decorators are left out of "Show code" (`excludeDecorators`), so the layout wrapper doesn't end up in the copied snippet |
| `story-viewport.ts` | `viewportSizeFlags(wide, handset)`: `NdwuSizeFlags` from one module-level signal on `matchMedia(HANDSET_BREAKPOINT)`; `adaptiveSizeBinding(mode)`: `[adaptiveSize]="sizeFlags"` for `viewport`, nothing for `unbound` | `adaptiveSize` takes signals, which no control can edit. The Viewport toolbar resizes the preview iframe, so a media query follows it. `Breakpoints.Handset` is where dropdowns and modals of the kit go mobile. The binding stays as written in "Show code", which shows the app pattern |
| `story-controlled.ts` | `withControlledArgs(output, toArgs)`: a story decorator that calls `useArgs` and passes the story args with the output wrapped, so it logs the action and writes the new value into args; `output` accepts only function-valued `<name>Change` args. On the docs page (`viewMode === 'docs'`) it returns the story unchanged, so docs stories stay uncontrolled | A controlled component reports its new value through a `<name>Change` output; without the decorator a user change updates the native element while the arg and the Controls panel keep the old value. A decorator, because "Show code" (`excludeDecorators`) calls `render` again outside the hooks context, where `useArgs` throws. On the story's own page the template string stays the same, so Storybook only pushes props and the story doesn't remount. Storybook's Angular docs renderer remounts the story on every args update, so on the docs page the focused control would lose focus |
| `story-form.ts` | `submitArgType`, `submitProps(args)` (prevents navigation, logs `FormData` entries), `nativeFormTemplate(fields)` (`<form (submit)>` with the fields and a submit button), `withNativeForm` (stack layout, `NdwuButtonComponent` import), spread with `decorators: [...withNativeForm]` | A native submit would navigate the preview iframe away; the entries show what `name` / `value` / `required` send. The `submit` prop name, the button and its import live in one file |
| `story-router.ts` | Adds story-level in-memory Router providers, imports `RouterLink` and wraps the story in `sb-router-url`; `withRouter` is an array of three decorators (`applicationConfig`, `moduleMetadata`, `componentWrapperDecorator`), spread with `decorators: [...withRouter]` | Router setup stays local to stories that need it; the wrapper is excluded from "Show code" |
| `story-template.ts` | `lines(items)` joins templates of a fixed story, one element per line; `group(items)` wraps them in a `<div>` row for `withStackLayout` | One shared helper replaces a copy in every story file |
| `router-url.component.ts` | Projects its content and shows the current Router URL in a `sb-note` paragraph | A router story makes navigation visible without changing the Storybook iframe URL |

### Home page

| File | What it does | Why it is built this way |
|---|---|---|
| `src/storybook/introduction/introduction.mdx` | Root docs page `Introduction`, first in the sidebar, opened at `/`; embeds the `Home` story | MDX can't render Angular components; `<Story of>` renders the Angular page inside it |
| `src/storybook/introduction/introduction.stories.ts` | `Hidden/Introduction`, tag `!dev`; renders `<sb-introduction />` through `render` + `moduleMetadata` | Hidden from the sidebar but still in the index, so the MDX can embed it. A title other than `Introduction` keeps the MDX a single sidebar leaf. No `component:`, because Compodoc doesn't read `src/storybook` and would log "Component not found" |
| `src/storybook/introduction/sb-introduction.component.*` | Logo, name, version from `src/lib/package.json`, cards made of `ndwu-card` and `ndwu-badge` | Kit components follow the Theme toolbar; explicit `size` keeps the Size toolbar off the page. Left click emits `NAVIGATE_URL` on the preview channel, like addon-docs MDX links, so toolbar globals survive; `href` + `target="_top"` keep middle-click and new tab. In Dark the logo gets `invert(1) hue-rotate(180deg)`, so its blue part stays blue |
| `src/storybook/introduction/introduction.cards.ts` | `INTRODUCTION_CARDS`: group, name, docs id, description, ready | Hand-written: a new docs page adds its card |
| `src/storybook/assets/logo.svg` | Logo for the home page and the manager | Lives outside `src/lib/assets`, which ships with the package |

## Outside `.storybook/`

| File | Storybook part |
|---|---|
| `angular.json` | `storybook` and `build-storybook` targets on the `ndw-ui-kit` project: port 6006, no browser auto-open (`open: false`), `experimentalZoneless`, `styles` + `includePaths: ["src/lib"]` for kit SCSS aliases, Compodoc on `tsconfig.lib.json` with private/protected/internal members off, output `dist/storybook`. `browserTarget: "ndw-ui-kit:build"` is required by the builder (without it, `start-storybook` fails); `lint` covers `.storybook/**/*.ts` |
| `package.json` | Scripts `storybook`, `build-storybook` (generate sprites first); `fmt`, `lint:ts-src`, `lint:styles` include `.storybook/`. Storybook packages, Compodoc, `@angular-devkit/build-angular` and its devkit peers pinned to the `@angular/build` / `@angular/cli` version, webpack pinned through `resolutions` |
| `tsconfig.json` | References `.storybook/tsconfig.json` |
| `tsconfig.lib.json` | Includes only `src/lib/**`, excludes `**/*.stories.ts` |
| `eslint.config.js` | `eslint-plugin-storybook` flat recommended config; the `sb-` selector override covers `.storybook/**/*.ts`, `src/**/*.stories.ts` and `src/storybook/**/*.ts` |
| `.stylelintrc.js` | Override for `.storybook/**/*.scss`: `no-unsupported-browser-features` also ignores `css-has`, for the home page's docs-frame rule |
| `scripts/collect-base-icon-usage.ts` | Ignores `*.stories.ts`, so icons used only in stories don't enter the core sprite |
| `.gitignore` | `.storybook/documentation.json`, `debug-storybook.log` |

## Build

- Storybook for Angular builds with webpack through `@angular-devkit/build-angular`; the library and the playground stay
  on `@angular/build` (esbuild). `build-angular` is used by the Storybook targets only.
- `@angular/build`, `@angular/cli` and the three devkit packages are bumped together; the webpack `resolutions` pin keeps
  one webpack copy (`yarn why webpack`).
- Compodoc reads the library once at start. After changing a component's inputs, restart Storybook.
- Move to Vite (`@storybook/angular-vite`) with the Angular 21 upgrade; Storybook 11 drops Angular 20.
